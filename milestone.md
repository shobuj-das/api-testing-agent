# AI API Testing Agent — Milestone Plan

## Project objective

Build a maintainable API testing system in which AI produces structured, validated planning and analysis data, while deterministic Python code performs HTTP requests, assertions, workflow execution, logging, and reporting.

The system must never execute arbitrary Python or shell commands generated by an LLM.

## Engineering guardrails

```text
AI reasoning
    -> Pydantic schema validation
    -> deterministic business validation
    -> deterministic HTTP execution
    -> structured result
    -> AI analysis / bounded next decision
```

- LLM output is data, never executable code.
- Environment defaults to `staging`; production requires an explicit opt-in.
- Passwords, API keys, bearer tokens, and common credential-shaped log text are masked.
- Every loop has explicit limits for iterations, retries, test count, and timeouts.
- AI conclusions preserve evidence, assumptions, calibrated confidence, and concise reasoning summaries—not hidden chain-of-thought.

## Completed milestones

### Milestone 1 — Conventional API automation foundation

Status: complete

- Added path/query/header/JSON/auth/timeout support, request/response capture, logging, production safety checks, and sensitive-value masking.
- Added unit tests for configuration safeguards, client request construction, and masking.

Status: complete

Status: complete

## Definition of done for the initial MVP

The MVP is complete when a user can run a command equivalent to:

```powershell
python scripts/run_agent.py --spec examples/restful_booker/openapi.json
```

and the framework can parse the API, produce validated structured tests in mock or provider mode, remove duplicates, present tests for approval, execute approved tests, make deterministic assertions, classify failures, execute supported workflows, and write a final QA report.

## Definition of done for the full AI agent

The full AI agent is complete when:

- The user can switch between LLM providers (OpenAI, Anthropic, Gemini, Ollama) by changing one environment variable.
- Test failures automatically trigger notifications to configured Discord and/or Telegram channels.
- Any REST API can be tested by providing an OpenAPI spec and a YAML project configuration profile.
- All automated tests pass, including new provider and notification tests.
